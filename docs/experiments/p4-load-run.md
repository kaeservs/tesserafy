# P4 — fifty transcripts in one run

**Date:** 2026-09-20 · **Gate:** 50 transcripts ingest in one run; cost per
transcript recorded; failures are per-file.

## Result

| | |
|---|---|
| Files | 50 (48 valid, 2 deliberately malformed) |
| Imported | 48 |
| Failed | 2 — and only those 2 |
| Wall clock | **78 s** at concurrency 4 |
| Cost | $0.74 total, **$0.0153 per transcript** |
| Per transcript | 1417 tokens in, 331 out, median 5.7 s, slowest 15.1 s |
| Produced | 192 segments, 99 signals |

Re-running the same directory skips all 50 in about a second and spends
nothing, because each file carries a source key unique per company.

## Why two files were broken on purpose

A run of fifty clean files says nothing about the half of the gate that
matters. The generator writes two that fail differently — one that is not
WebVTT at all, one whose cue ends before it starts — and both failed alone,
each naming its own line number, while the other forty-eight finished:

    load-broken-1.vtt: Not a WebVTT file: it must start with WEBVTT (line 1)
    load-broken-2.vtt: Cue ends (10000ms) before it starts (30000ms) (line 3)

The run exits non-zero so a script above it knows, and the report records
every file's own outcome.

## Where the data went

A separate company — "Load test — synthetic, not a customer" — with no members,
so nobody's account can see it. Two reasons: fifty synthetic conversations
would bury the ten real ones during QA, and a second tenant exercises the
isolation guarantees at some volume rather than at two rows.

The transcripts themselves are generated by `pnpm make:transcripts` and are
**not** suitable for measuring quality: the sentences come from a handful of
shapes. `services/eval` is where accuracy is measured, on labelled data.

## What it did not test

Fifty files of six cues each is throughput, not load. A real hour-long call
produces far more segments, and the embedding step — one Ollama call per
segment, sequential — is the part most likely to hurt at that size. Worth
re-running once a real transcript exists.
